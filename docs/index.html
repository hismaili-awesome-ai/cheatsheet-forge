02

Four agents, one gate

Each stage hands the next a narrower artifact. The reviewer is the only one that goes back to the raw source, and the pipeline stops dead in front of you before anything is published.

/analyze analyst · reads raw

Extracts commands into a structured inventory, deduplicated and parameterised. The only agent that touches unsanitised source, so every credential dies here.

/write writer · never reads raw

Turns the inventory into the sheet. Works only from what the analyst extracted, and emits nothing that lacks a source reference.

/review reviewer · reads raw again

Audits the sheet against the dumps from scratch. Checks provenance both ways, and judges whether destructive commands carry honest warnings.

/publish publisher · local only

Builds the docs site and serves a preview. It has no ability to push, by construction — the last step out the door stays yours.

▣ human gate

/forge <topic> runs the first three in order and then stops, whatever the verdict. A blocked review is never routed around: it points back at the writing or the extraction, and never at publishing. commands/forge.md

03

Two rules a model cannot talk its way past

Everything else in the pipeline is an instruction, and an instruction is something a model can reason around. These two are a PreToolUse hook: the write is refused by a Python script before the tool runs.

Which binary belongs to which technology is declared in a tech profile, so teaching the guard a new stack is one YAML file and never an edit to blocking code. A binary owned by two stacks — pod is CocoaPods and a Ruby gem — simply appears in both.

04

Bring your own repository

The plugin holds no knowledge of any particular repo. Where sources live, where the site builds, and whether sheets are <topic>/<topic>.md or <topic>.md all come from a config file that stays in your repo, under your control.

1 · install once per machine

Add the marketplace and install the plugin. Claude Code clones and caches it for you; you never clone anything yourself.

2 · init once per repo

/cheatsheet-forge:init inspects what is already on disk, infers your layout, and gitignores the raw dumps. Existing content is read, never modified.

3 · drop dumps per topic

Paste terminal output into the sources folder. It is gitignored and exempt from the guard, so unsanitised text is safe there — and only there.

4 · forge per topic

/forge <topic> and read the verdict. Unknown technologies work without a profile: the reviewer finds the official docs and reports at reduced confidence.
