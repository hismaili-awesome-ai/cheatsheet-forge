What it actually cost

Every number here was measured, not imagined

These are the defects found by hand in one cheat sheet, built from one real OpenShift session. Counting them is what produced this plugin.

4 commands invented outright Plausible flags, correct-looking syntax, no such subcommand. Nothing in the source ever said them.
10 / 60 real commands silently dropped Omission leaves no trace. The page looked complete because nothing marked what was missing.
2 working commands "corrected" into broken ones They ran fine on a real cluster. An eager editor improved them into failure.
and the obvious fix failed too

So we had a second model review the first one's work. Handed a tidy summary of the source instead of the source, it found one defect out of nine. Checking AI with AI is not free — it only works if the reviewer is forced back to the raw evidence, blind to the story.

The fix

Nothing ships that cannot name its source

Three rules, each one answering a failure above. Two of them are Python, not persuasion — a PreToolUse hook refuses the write before the tool runs, and no amount of clever reasoning gets around it.

Provenance

A citation or nothing

Every command carries a source_ref pointing at the exact dump file and line it came from. No reference, no output. Invention becomes structurally impossible rather than discouraged.

Adversarial review

The reviewer re-derives

It reads the raw dumps first and is told nothing about what the writer did or intended. It diffs source against document in both directions, so an omission is as loud as an invention.

commands/review.md:12
Deterministic guard

Secrets never reach a file

Tokens, keys, passwords, home paths, private IPs and internal DNS are blocked by a hook on every governed write — and a command belonging to another technology cannot land in the wrong sheet.

Inert everywhere else

The hook runs on every write in every project you open, and returns immediately unless the file sits inside a repo you explicitly initialised. Your unrelated codebases are never scanned and never blocked. tests/test_guard.py:175

Four agents, one gate

It stops in front of you, every time

Each stage hands the next a narrower artifact. The pipeline never publishes on its own, and a blocked review is never routed around.

01 · analyst /analyze

Extracts commands into a structured inventory, deduplicated and parameterised. The only agent that touches unsanitised source, so every credential dies here.

02 · writer /write

Turns the inventory into the sheet. Never reads the raw dumps, and emits nothing lacking a source reference.

03 · reviewer /review

Audits the sheet against the dumps from scratch. Checks provenance both ways and judges whether destructive commands carry honest warnings.

04 · publisher /publish

Builds the docs site and serves a local preview. It has no ability to push, by construction — the step out the door stays yours.

▣ human gate

/forge <topic> runs the first three in order and then stops, whatever the verdict. A blocked review points back at the writing or the extraction — never at publishing. commands/forge.md

Two commands

Nothing to clone

Run these inside Claude Code from any directory. It fetches and caches the plugin for you.

/plugin marketplace add https://github.com/hismaili-awesome-ai/cheatsheet-forge.git
/plugin install cheatsheet-forge@cheatsheet-forge
/cheatsheet-forge:init

The last one runs once in the repo that holds your sheets. It reads what is already on disk, infers your layout, and gitignores the raw dumps. Existing content is inspected, never modified.

RequiresPython 3.8+ as python3. No pip install — PyYAML is used when present, and a built-in parser stands in when it is not.
Your repo, your rulesSource folder, site folder, file layout and the client names the guard blocks on all live in a config file that stays in your repo.
